When performing the query with just { transactions { description } } in GraphQL, the server returned exactly one field per record over the network. Compared to the traditional REST endpoint, which would return the entire transaction object including the ID, amount, type, and timestamps. With GraphQL, this prevents something known as "over-fetching" which can be useful in real-world mobile applications, where users might be on slow or limited cellular networks. By allowing the client to request only the precise data needed for a specific UI component, GraphQL significantly reduces bandwidth consumption and improves the application's overall loading speed.
